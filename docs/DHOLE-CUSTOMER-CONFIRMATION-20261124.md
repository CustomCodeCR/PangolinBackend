# Customer delivery confirmation — PR #274

The customer receives the Pricing success message only on server-confirmed creation. Pending, rejected and uncertain outcomes remain distinct from confirmed. Both GIO and the official wizard use a bounded (two-minute) GET-only receipt poll, protected by the original random submission key plus quote ID, and the original authenticated user when applicable. No PII or external UUID is returned by this endpoint. GIO same-tab receipt handoff retains the key in session storage for the existing 30-minute handoff; never in a URL. If the user closes the screen, email is the intended notification.

DholeOfficialConfirmationEmail is an independent, unregistered Graph-only pass. It queries confirmed rows with a verified UUID, atomically reserves one email per quote, sends only to the stored contact address, and records Graph acceptance or an uncertain outcome. It does not send on a local save, 2xx alone, or a failed/unverified POST. It never reclaims ambiguous mail or repeats the Pricing POST. Graph 202 is not proof of inbox delivery. For now Spanish copy is used (no durable submission language field). Requires explicit ConfirmationEmailEnabled, Graph credentials, additive schema upgrade, authorized dispatcher host and independent Pricing confirmation. No real mail or POST is sent by this commit. The two-minute UI polling window is a deliberate bounded default; the email is independent of that window once the worker is connected. No flags or deployments changed.
