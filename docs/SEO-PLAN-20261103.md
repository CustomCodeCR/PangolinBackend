# Plan integral de presencia orgánica y búsqueda con IA — Grupo Castro Fallas

**Fecha:** 3 de noviembre de 2026. **Rama:** `main-2`. **Ámbito:** Grupo Castro Fallas, Aduanera Castro Fallas, Transporte Castro Fallas y Neriteka.

## 1. Estado implementado (2026-11-03)

- `frontend/nuxt` es un frontend real Nuxt 4 con SSR. Renderiza la web pública (Inicio, Nosotros, Servicios, cuatro fichas de servicios y Noticias) reutilizando los componentes Vue existentes. No significa que el 100% de Vue esté migrado.
- Nuevas rutas públicas: `/empresas`, `/empresas/aduanera-castro-fallas`, `/empresas/transporte-castro-fallas`, `/empresas/neriteka`. Incluyen HTML inicial, H1, canonical, metadatos, Organization/BreadcrumbList/ItemList, enlaces internos, preguntas visibles y contenidos empresariales.
- El sitemap de Nuxt incluye rutas públicas canónicas y noticias publicadas no expiradas; `robots.txt` establece una política separada para OAI-SearchBot y mantiene `GPTBot` deshabilitado según el criterio anterior.
- Las páginas de login, cotizaciones, tracking, itinerario y administración siguen en Vue mediante gateway para proteger la compatibilidad de sesiones y funcionalidades. No deben indexarse.
- `frontend/seo/keyword-map.json` permite relacionar páginas y consultas principales; no corresponde a la etiqueta `meta keywords`, que no aporta SEO en Google.
- Se integró en `main-2` después de aprobar las pruebas de Nuxt, sitemap, datos estructurados, 301/404, integración noticias, Docker, Nginx y Compose. **No se ha ejecutado despliegue a producción ni enviado el sitemap a un motor de búsqueda desde este cambio.**

## 2. Activación técnica y publicación (primeros siete días)

- [ ] Revisar diseño, idioma, navegación y experiencia móvil y escritorio de las páginas nuevas; contrastarlas con el diseño Vue actual. Validar logos, enlaces, metadatos, textos empresariales y accesibilidad.
- [ ] Desplegar al entorno de previsualización Nuxt. Ejecutar el smoke SSR con JavaScript desactivado y revisar que el HTML contenga contenido real, H1 y canonical correctos.
- [ ] Pasar por canary del gateway conservando las rutas privadas actuales. Probar CMS, noticias, login, cotizador, tracking, SignalR, salud del backend y rollback. Promover a producción únicamente después de validar estas funciones.
- [ ] Coordinar los dominios con Fennec: Pangolin gestiona `www.logisticacastrofallas.com`, mientras la raíz sin `www` está en otra aplicación. Acordar un host canónico único antes de imponer redirecciones 301 o canonicals cruzados. Evitar duplicados y conflictos.
- [ ] Verificar HTTP: páginas públicas 200; `/home` 301; URLs inexistentes 404; sin contenido secreto en HTML ni sitemap; noindex/autorización adecuada para páginas privadas. Examinar 5xx y WAF/CDN.
- [ ] Confirmar acceso a `/robots.txt` y `/sitemap.xml` desde el dominio real, sin bloqueo de Googlebot, Bingbot, OAI-SearchBot ni robots pertinentes al buscador de IA. La política sobre rastreo para entrenamiento se define por separado.
- [ ] Revisar `hreflang` solo si se publican páginas diferenciadas ES/EN con URL propia; no inventar `hreflang` para un selector de idioma sin URL independiente.

## 3. Indexación y diagnóstico (días 1 a 15)

- [ ] Verificar propiedad de dominio y `www` en **Google Search Console** y el sitio en **Bing Webmaster Tools**.
- [ ] Enviar el sitemap público y revisar su lectura, páginas descubiertas y errores; inspeccionar URLs principales individualmente. No utilizar API Indexing de Google para páginas ordinarias (la API está limitada a tipos admitidos).
- [ ] Documentar páginas `Descubierta, actualmente sin indexar`, `Rastreada, actualmente sin indexar`, canonical alternativa, bloqueadas por robots, redirecciones, 404 y errores del servidor.
- [ ] Conservar un inventario: URL, empresa, página de servicio, indexable sí/no, title, description, H1, canonical, estado HTTP, texto visible SSR, schema, enlaces internos y última revisión.
- [ ] Medir por separado el dominio raíz y `www`; consultar las consultas con marca y sin marca. Corregir primero bloqueos, duplicidad de host y contenido inaccesible.

**Importante:** una URL en un sitemap es una solicitud de descubrimiento, no un mecanismo para forzar que Google o Bing la indexen.

Evitar páginas «SEO» vacías, inventar certificados, oficinas, autorizaciones, equipos o servicios. Los hechos y números corporativos deben revisarse con gerencia. Evitar afirmaciones absolutas sobre tiempos, costos o autorizaciones aduaneras.

## 6. Medición mensual: Google, Bing y asistentes con IA

- **Google Search Console:** impresiones, clics, CTR, posición media, consultas sin marca, indexación, errores y rendimiento de IA generativa cuando la propiedad tenga acceso.
- **Bing Webmaster Tools:** impresiones, clics, indexación y el informe **AI Performance** para citas en Microsoft Copilot y experiencias compatibles.
- **Analytics y CRM:** tráfico orgánico, referencias identificables desde asistentes, solicitudes de contacto y cotizaciones atribuibles.
- **Auditoría manual de IA:** repetir mensualmente un conjunto fijo de preguntas en ChatGPT, Gemini, Claude y Copilot. Guardar fecha, país, pregunta, respuesta, marcas recomendadas, URLs citadas, resultado con o sin marca y capturas. Esto es una muestra, no un ranking oficial.
- **Preguntas sin marca sugeridas:** «¿Qué agencia aduanal me puede ayudar a importar a Costa Rica?», «¿Quién coordina carga LCL en Costa Rica?», «¿Dónde cotizo transporte terrestre Panamá–Costa Rica?», «¿Qué opciones hay de almacenamiento fiscal de importaciones en Costa Rica?».
- **Preguntas con marca:** «¿Qué es Grupo Castro Fallas?», «¿A qué grupo pertenece Neriteka?», «¿Qué hace Transporte Castro Fallas?», «¿Cómo contacto Aduanera Castro Fallas?».
- **Registro de línea base:** medición antes/después con periodicidad mensual. No prometer posiciones, citaciones ni plazos de indexación.

## 7. Aprobaciones y riesgos

| Trabajo | Dependencia |
|---|---|
| Deploy público Nuxt en WWW | Validación de diseño, pruebas y acceso al runner/reverse proxy |
| Dominio raíz/WWW y 301 | Aprobación del equipo Fennec y coordinación de DNS/Traefik |
| Google Search Console y Bing Webmaster | Acceso de propiedad y verificación, envío del sitemap |
| Perfiles de empresa | Autorización y datos empresariales verificables |
| Contenidos por modalidad y marcas | Revisión comercial y regulatoria |
| Métricas de IA | Disponibilidad de datos por plataforma y medición manual |

**No existe una configuración técnica que obligue a Google, ChatGPT, Claude, Gemini o Copilot a indexar, citar o recomendar una empresa.** La estrategia crea páginas rastreables y verificables, contenido útil y autoridad pública para mejorar la elegibilidad y medir resultados.
